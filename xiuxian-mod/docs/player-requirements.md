## 三、设计说明（为什么这么做）

### 关于"用网上玩家皮肤"

**没有直接抓取网上皮肤**，原因有二：

1. **版权**：网上的皮肤是作者作品，直接打包进 mod 分发有授权问题
2. **不必要**：我把人形怪的骨架做成了**标准 64×64 人形 UV**，也就是说
   **任何玩家皮肤都能直接替换上去**（改一个文件名即可）。这比内置几张固定皮肤更灵活

自制贴图的好处是能按修仙主题做差异化：血魔修士的血痕、傀儡队长的金属分节环、
魔道统领的「魔」字符、虚空道主的金线滚边——这些都是通用皮肤给不了的。

### 关于灵叶从"物品"变成"余额"

原来的实现是**实体物品**：`leavesOf()` 数背包里的 `lingye` 物品，
`giveLeaves()` 往背包里塞。问题是杀怪/任务奖励会**持续占满背包**。

改法：

- 新增 `CultivationData.leaves` 余额字段（存档 + 网络同步）
- **奖励直接进余额**（杀怪、任务、副本通关）
- `leavesOf()` = 余额 + 背包里的实物（兼容老存档与手工合成的灵叶）
- `spendLeaves()` 先扣余额，再扣实物
- 商店加「存入灵叶」按钮，把手上实物转成余额

**为什么保留实物物品**：`hongmeng:lingye` 是约 15 条合成配方的原料
（造化丹、筑基丹、破境丹、双道宫丹、灵根祭坛、纪元门框…）。
删掉物品会让这些配方全部失效。所以是"余额 + 实物并存"，而不是简单替换。

### 经济平衡的目标

调价的目标是让**练气期玩家在一段合理游戏时间后能买到第一颗丹药**。
原设计的"仙品丹 500 片，一次采药 1~3 片"意味着要采 200 次药，
而杀怪只掉 1 片、8% 概率——这条曲线在前期是断的。

## 五、这一轮踩到并修掉的坑

### `worldgen/structure` 的 `biomes` 不能写裸数组

第一次构建后**服务端直接起不来**：

```
Failed to parse hongmeng:worldgen/structure/xiuxian_yard.json
Caused by: Not a string: [...]; Not a JSON object: [...]
```

原因：1.20.1 结构的 `biomes` 字段只接受**字符串**（群系或标签引用）或**标签对象**，
不接受裸数组。原版 `village_plains.json` 用的是
`"biomes": "#minecraft:has_structure/village_plains"`。

修法：建自己的群系标签 `data/hongmeng/tags/worldgen/biome/has_structure/xiuxian_yard.json`，
结构里写成 `"biomes": "#hongmeng:has_structure/xiuxian_yard"`。

**教训**：`data/` 下的 JSON 写错不是"少个功能"，而是**整个服务器起不来**。
新加 worldgen 内容后必须真的跑一次服务端，离线断言挡不住这类错误。
