# ⚠️ 本轮修掉的两个真实 bug（你之前可能撞到过）

## 1. 雷鹰会让服务端崩溃（已修）

**症状**：只要**已加载区块里有一只雷鹰**，服务端启动后约 2 秒必崩：
```
java.lang.IllegalArgumentException: Can't find attribute minecraft:generic.flying_speed
  at ThunderEagleEntity.aiStep(ThunderEagleEntity.java:130)
```

**原因**：雷鹰用了 `FlyingMoveControl`（飞行控制器），但属性表里没注册 `FLYING_SPEED`。

**为什么之前没发现**：我测的是"服务端能干净启动"，而那时区块里还没有雷鹰——
这个 bug 的触发条件是"**区块里有雷鹰**"，不是"能启动"。

**修法**：给**所有**妖兽都注册 `FLYING_SPEED`（地面怪多一个用不到的属性完全无害），
这样"以后谁再加一只飞行怪忘了加属性"这类崩溃再也不会发生。

**已验证**：强制加载区块 + 召唤雷鹰，服务端活过 45 秒，
雷鹰 Y 坐标从 64.0 变到 62.487（**在真的飞**），无崩溃、无异常。

## 2. 「修仙小院」结构永远不生成（已修）

**症状**：启动日志里有 `Couldn't load structure hongmeng:xiuxian_yard`
```
ResourceLocationException: Non [a-z0-9/._-] character in path of location:
  hongmeng:meditation_cushion[facing=north]
```

**原因**：结构 NBT 的 palette 把**方块状态串整个写进了 `Name`**：
```json
错误：{"Name": "hongmeng:meditation_cushion[facing=north]"}
正确：{"Name": "hongmeng:meditation_cushion", "Properties": {"facing": "north"}}
```
Minecraft 把 `Name` 当 `ResourceLocation` 解析，遇到 `[` 就抛异常。

**为什么之前没发现**：这个错误**不致命**（服务端照常启动），
而我的日志检查只 grep 了 `Failed to parse|Unbound values`，没覆盖 `Couldn't load structure`。

**修法**：两个结构 NBT 共修复 **10 条 palette 条目**（`xiuxian_yard` 7 条、`shenxiao_sect` 3 条），复查 0 剩余。

**已验证**：启动日志里结构报错 **0 条**。

> **这两个 bug 的教训**：
> 1. **"能干净启动"不等于"没问题"** —— 雷鹰的 bug 要"区块里有实体"才触发
> 2. **日志要 grep 全** —— 我漏了 `Couldn't load structure` 这一类"不致命但功能失效"的错误
> 3. 两个都是**子代理主动报告的**，不是我自己测出来的。诚实报告未验证项的价值就在这里。
