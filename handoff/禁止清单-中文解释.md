# 禁止事项清单（中文解释版）

> 给 3D 模型 AI 和交接人看：**什么绝对不能碰、为什么不能碰、允许的边界在哪里。**  
> 权限总表见 `BOSS-模型改造总表.md`；任务提示词见 `PROMPT-修订版.md`。

---

## 一、绝对禁止：两个文件

### 1. `BossLadder.java`

路径：

```text
xiuxian-mod/src/main/java/com/hongmeng/xiuxian/difficulty/BossLadder.java
```

**它是什么：**

8 只阶梯 BOSS 的“唯一强度真源”。里面有：

- BOSS 顺序：傀儡祖师 → 万兽之主 → 血魔老祖 → 焚天炎帝 → 虚空龙帝 → 虚空道主 → 仙庭之主 → 恶；
- 每只 BOSS 的设计境界、所在维度、维度档位；
- 每只 BOSS 的 **目标 HP / 目标 ATK**；
- HP/ATK 阶梯步长（1.30~1.70）的验收依据。

**为什么不能动：**

模型重制只应该改变“看起来怎么样”，不应该改变“打起来怎么样”。  
一旦改了这个文件，8 只 BOSS 的 HP、攻击、阶位顺序会全部漂移，之前做的数值平衡、TTK、阶段强度全部作废。

**允许做什么：**

- 只读、引用、对照；
- 把它的数值抄进 `NOTES.md` 做验收对照；
- 不允许改数值、不允许改顺序、不允许改字段含义。

---

### 2. `BossAttackKit.java`

路径：

```text
xiuxian-mod/src/main/java/com/hongmeng/xiuxian/entity/BossAttackKit.java
```

**它是什么：**

BOSS 攻击系统的核心状态机，负责：

- 攻击池：SLAM / SHOCKWAVE / SUMMON / SPELL / BREATH / AMBUSH / CATACLYSM / CHARGE / ENRAGE；
- 每招的前摇、判定、后摇；
- 阶段一/二/三的攻击池扩展；
- 召唤小怪的表；
- 客户端同步字段：`bossState`、`bossAttack`。

**为什么不能动：**

模型 AI 要做的是“动画跟攻击对得上”，不是“改攻击本身”。  
如果为了动画去改攻击时序、攻击池、召唤表，会直接改变 BOSS 的实际战斗行为，也会让 `BossLadder` 的强度验收失效。

**允许做什么：**

- 只读 `bossState()` / `bossAttack()` / `bossPhase()` 这些**同步字段**；
- 在实体/动画控制器里根据它们播放对应动画；
- 不允许改攻击池、前摇/后摇、伤害、召唤、同步逻辑。

---

## 二、禁止改战斗数值与阶段逻辑

| 禁止项 | 为什么 |
|---|---|
| BOSS 基础 HP / ATK | 会破坏 `BossLadder` 的 8 阶平衡 |
| BOSS 品阶（BOSS/OVERLORD） | 影响血条、光晕、伤害倍率、掉落 |
| 境界缩放 / 怪物强度下限 | 影响全模组怪物，不只是 BOSS |
| 阶段阈值 66% / 33% | 模型动画可以跟着阶段走，但不能改阶段本身 |
| 阶段属性倍率（+30%/+55% HP、+25%/+50% ATK） | 会改变 BOSS 难度 |
| 三阶段回血（每 40 tick 1.2%） | 属于战斗机制，不是模型表现 |
| 伤害软上限 / 护甲结算 / 攻击距离 | 模型变大不能顺手改战斗规则 |
| 掉落表 / 奖励 / 经验 | 不属于模型任务 |
| BOSS 攻击命中判定 | 动画可以配合，但不能改判定逻辑 |

**一句话：模型可以决定“看起来多大、怎么动”，不能决定“打多少血、什么时候转阶段、攻击怎么判”。**

---

## 三、禁止改其他实体和注册

| 禁止项 | 说明 |
|---|---|
| 改其他实体（非 8 只 BOSS） | 本次范围只有 8 只 BOSS；其他怪/动物/NPC 不要碰 |
| 改实体注册 id | 例如不能把 `beast_boss` 改成别的名字；存档/掉落/命令都会坏 |
| 改 `ModEntities` 中其他实体的 `sized()` | 判定箱只允许 8 只 BOSS 在“视觉超出”时有条件同步 |
| 改实体属性/`createAttributes()` | 模型 AI 不做数值 |
| 改 `ClientSetup` 中其他实体的 Renderer | 只允许 8 只 BOSS 的注册迁移 |
| 改 ModelLayer 名并影响其他实体 | 新增/改层必须只影响这 8 只 |

**特别说明：**

- `ModEntities.java` 不是 Renderer 注册处；注册在 `ClientSetup.java`；
- “改判定箱”不是默认允许。只有视觉尺寸明显超出时才允许，并且必须逐只测试、写进 `NOTES.md`。

## 四、禁止改依赖与构建

| 禁止项 | 说明 |
|---|---|
| 升级/降级 GeckoLib | 固定 **GeckoLib 4.8.4**，`libs/geckolib-forge-1.20.1-4.8.4.jar` |
| 改 Forge / Minecraft 版本 | 固定 Forge 47.4.0 / MC 1.20.1 |
| 删除 `build.gradle` 的 GeckoLib 依赖 | 会导致全项目编译失败 |
| 改 `build.gradle` 其他依赖/仓库 | 模型任务不需要 |
| 改 Gradle/Java 版本 | 保持 Java 17 / Gradle 8.8 |
| 把 `build/`、`run/`、`.gradle/` 打进交付 | 不是源码，体积大且可能污染 |

---

## 五、禁止改客户端/服务端边界

| 禁止项 | 说明 |
|---|---|
| 改网络包 / `ModNetwork` | 模型动画只读已有同步字段，不要新增包 |
| 改服务端 AI / 行为 | 模型不决定 BOSS 怎么追人、怎么放技能 |
| 改维度 / 群系 / 结构 | 不属于模型任务 |
| 改装备 / 武器 / 物品 / 方块 / 配方 | 不属于模型任务 |
| 改其他 UI / HUD / 镜头系统 | 除非是模型渲染必需的可见性调整，且要单独说明 |

## 六、禁止的视觉/技术做法

| 禁止做法 | 正确做法 |
|---|---|
| 用 `_emissive` 命名发光贴图 | GeckoLib 4.8.4 自动发光用 `_glowmask.png`；旧品阶层用 `_glow.png` |
| 两套发光命名混用 | 每只 BOSS 选定一种 |
| 只改 PNG 尺寸不重排 UV | UV 必须按新贴图完整重排，0 越界/0 重叠 |
| 把旧原版模型的 `_glow.png` 直接套到 Geo UV 上 | Geo 模型要重新做 UV 和发光贴图 |
| 把 `bossRenderScale`/`giantScale` 烘焙进模型 | 只在自定义 GeoRenderer 里乘一次 |
| root 骨骼做位移/旋转来表现攻击高度 | 垂直动态放 `body/hip/chest`；root 保持无位移无旋转 |
| 无限放大模型 | 建议 +10%~40%；超出判定箱要有条件同步，并实测 |
| 为了“看起来大”改判定箱 | 先保持判定箱，确实超出再改，且只改这 8 只 |
| 不备份就删旧 Renderer/Model | 先备份、保留 diff，验收后再清理 |
| 引入外部模型/贴图/动画 | 只能自制，避免版权和坐标/UV 不可控 |
| 每帧 new RenderType | 遵守项目现有缓存规则，避免客户端崩溃/性能问题 |
| 把 `references/round6` 的预览图直接当运行时贴图 | 预览图只做参考，运行时贴图要单独制作 |

## 七、禁止的交付行为

| 禁止行为 | 说明 |
|---|---|
| 不跑 `build` 就交付 | 必须 `.\gradlew.bat build --offline -x test` 通过 |
| 不跑 `verify_handoff.py` 就交付 | 必须 PASS |
| 两个禁改文件哈希变了还继续交付 | 直接判 FAIL |
| 不写改动说明/NOTES | 无法审查，不能交付 |
| 只给截图不给源码 diff | 无法合并，不能交付 |
| 交付夹带 `build/`、`run/`、日志、临时文件 | 只交源码/资源/说明 |
| 遇到阻塞偷偷改核心 | 必须停止并报告 |

---

## 八、允许的“大改”边界（避免误解）

以下都属于**允许**：

- 新增/删除/重命名骨骼；
- 调整骨骼父子关系、pivot、比例、剪影；
- 把 BOSS 做得更大（建议 +10%~40%）；
- 强化专属特征：角、翼、尾、甲、胸核、日轮、操纵线等；
- 重做模型、贴图、UV、动画；
- 新增 `GeoBossEntity` / `GeoModel` / `GeoRenderer`；
- 改这 8 只 BOSS 的 Renderer 注册；
- 视觉尺寸超出判定箱时，同步调整这 8 只的 `sized()`（有条件）；
- 迁移 `BossPhaseRenderer` / `BossFormRenderer` 的旧表现逻辑到 Geo 渲染器。

**但允许“大改”不等于允许“改战斗”。**  
模型再大、特征再夸张，也不能改 HP/ATK/阶段/攻击池/其他实体。

---

## 九、违反后的后果

1. `verify_handoff.py` 会直接 FAIL；
2. 8 只 BOSS 的数值/攻击/阶段可能整体失衡；
3. 存档、命令、掉落、玩家预期都会受影响；
4. 交付会被退回，必须回滚到 `FORBIDDEN.sha256` 对应的版本。

---

## 十、一句话记住

**骨骼、比例、特化、贴图、动画都可以大胆改；  
HP/ATK、阶段、攻击池、其他实体、GeckoLib 版本一律不要碰。**
